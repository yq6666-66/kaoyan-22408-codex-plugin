# 能力路由契约

## 基本规则

1. 先识别用户当前要完成的主任务，只选择一个主责 Skill。
2. 需要串联时，先完成当前主责，再明确建议下一步；不要在未获请求时替另一个 Skill 完成全部工作。
3. 按意图而不是题目数量路由。单题也可能需要错因闭环，多题也可能只是逐题讲解。
4. 只使用当前会话中用户明确提供的信息。不得假设存在后台账户、历史记录或跨会话记忆。
5. 信息不足时只请求会改变结果的最小补充项，并允许未知字段保持为空。

## 冲突处理

- “为什么落后、风险在哪里”交给进度诊断；“从现在到目标日怎么安排”交给规划。需要改计划时先诊断，用户确认后再由规划师重排。
- 已有计划并要求“今天做什么”交给执行器；没有计划且约束会影响长期分配时先交给规划师。
- 要求讲清题目或概念交给对应学科教练；要求聚类根因、安排间隔复测或判断掌握交给错题闭环。
- 要求冻结题面、计时、统一交卷和评分交给模考；即时讲解或普通专项练习交给学科教练。
- 试卷与真题结构分析交给真题分析；讲义、笔记与教材片段加工交给材料助手。
- 政治中的理论与答题方法交给政治教练；带“今年、最新、当前”的时政、报名、招生和考试安排交给官方信息核验。

## 推荐串联

- `官方信息核验 → 规划 → 执行`
- `学科辅导 → 错题闭环 → 进度诊断`
- `真题分析 → 对应学科辅导或错题闭环`
- `模考 → 错题闭环 → 进度诊断`

每次串联都把中间结果展示给用户。若需要跨会话继续，输出便携学习记录，而不是暗示插件已经保存。
