# Notion 学习大脑契约

## 定位与启用

Notion 是用户授权的远程学习笔记层，不是插件发布者的后台数据库。只有当前宿主提供 `Notion:search`、`Notion:fetch`、`Notion:notion-create-pages` 或 `Notion:notion-update-page` 等工具，且用户已经连接自己的 Notion 工作区时，才可以启用本契约。

如果 Notion 工具不可用、授权失效、目标页面不可访问或用户说“本次不记忆”“只读模式”，继续完成学习任务，但本轮不写入 Notion，并明确输出：

`Notion：未连接或本轮只读；仅使用当前会话内容。`

## 每轮流程

1. 先确定当前唯一主责 Skill；Notion 只负责检索和沉淀，不抢占学科讲解、规划、诊断或官方核验的主责。
2. 用一个明确主题调用 `Notion:search`，没有更窄过滤条件时传 `filters: {}`；命中页面后再用 `Notion:fetch` 读取完整内容。不得把外部连接源 URL 当作页面 ID 继续 fetch。
3. 优先更新用户明确指定的页面或已命中的相关页面。没有可靠目标时先询问目标页面；不得凭标题猜测并覆盖任意页面，也不得创建重复的“考研总笔记”。
4. 写入前重新 fetch 当前页面。更新现有内容必须使用精确的 `old_str`/`new_str` 对，保留用户原文、已有链接和未冲突段落；发现并发变化时保留双方内容并标记“待整理”。
5. 从本轮对话中提炼最小、可复用的增量：概念结论、解题方法、已确认的错因、复测安排、稳定学习偏好或经官方核验的事实。不要把整段对话、寒暄、未采用草稿或临时状态复制到 Notion。
6. 写入内容必须分离来源标签：`[用户材料]`、`[模型推导]`、`[Notion记忆]`、`[官方核验]`、`[待核验]`。Notion 旧笔记只能作为 `[Notion记忆]`，不能替代当前官方来源。

## 推荐笔记结构

每次增量尽量放入已有学科或专题页面，使用以下小节，而不是新建长篇流水账：

```markdown
## 本轮增量｜YYYY-MM-DD
- 结论：
- 适用条件：
- 易错点/复测：
- 来源：`[用户材料]` / `[模型推导]` / `[官方核验]`
- 下一步：
```

题目、讲义或笔记只保存用户当前会话实际提供且有权使用的必要摘要，不上传或重建整套题库、完整付费材料、答案库或长篇版权原文。官方事实必须保留机构、适用年度、发布日期、直接 URL 和绝对核验日期。

## 自动写入边界

- 默认允许结构化更新，但仅限对后续学习仍有价值且已在回答中呈现的内容；纯讲题、寒暄、临时问法和重复内容保持只读。
- 新计划先标为 `planned`，只有用户报告完成后才写成 `completed`；假设错因必须标为 `hypothesis`，未经复测不得写成已掌握。
- 不写入密钥、Cookie、身份信息、私人联系方式、设备路径、整段会话或未授权材料。
- 用户说“不要同步 Notion”“本次不记忆”或“只读模式”时，Notion 与 Obsidian 均禁止写入；用户说“忘记/删除”时先定位记录，默认移动到 Notion 回收站或归档位置，不直接永久删除。
- 写入失败不影响学习回答。输出可复制的最小 Markdown 增量，并说明失败原因；不得声称已保存。

## 与 Obsidian 的关系

两者都是用户控制的记忆层。若两者同时启用，先分别检索并在回答中区分 `[Obsidian记忆]` 与 `[Notion记忆]`；冲突时保留来源差异，当前官方事实以官方核验结果为准。一次回答只生成一个结构化学习结论，不重复写入整段内容。

回答在交接卡之后、Schema 1.1 JSON 之前增加一行状态：

- 成功：`Notion：已检索 N 条相关笔记；已更新 <页面标题>`
- 只读或无需更新：`Notion：已检索 N 条相关笔记；本轮无写入`
- 降级：`Notion：未连接或本轮只读；仅使用当前会话内容。`

Notion 工作区由用户和 Notion 服务管理。插件发布者没有 Notion Token、后台账号、同步服务或读取用户工作区的独立权限。
