# Obsidian 大脑契约

## 启用与降级

1. 每次 22408 Skill 开始时，检查当前用户目录下的 `.codex/kaoyan-22408/obsidian-brain.json`。Windows 默认位置是 `%USERPROFILE%\.codex\kaoyan-22408\obsidian-brain.json`。
2. 配置必须是 UTF-8 JSON，并包含：

```json
{
  "schemaVersion": "1.0",
  "enabled": true,
  "vaultPath": "绝对 Vault 路径",
  "projectRoot": "20-项目/考研 22408",
  "writeMode": "auto-structured",
  "retrievalScope": "project-first"
}
```

3. 只有配置有效、`enabled` 为 `true`、Vault 目录以及 Vault 根目录的 `AGENTS.md` 和 `00-系统/知识库索引.md` 都可读时才启用。
4. 不得猜测、扫描或补全 Vault 路径。配置缺失、损坏、越界、不可读，或宿主没有本地文件权限时，继续完成原学习任务并输出：`Obsidian：未连接（原因）；本轮使用会话信息。`
5. 用户说“本次不记忆”或“只读模式”时仍可检索，但本轮禁止写入；用户说“关闭大脑”时，提示使用仓库配置脚本执行 `disable`，不得直接猜测配置位置以外的文件。

## 任务开始：有限检索

1. 先读 Vault `AGENTS.md`、`00-系统/知识库索引.md`、`projectRoot/主页.md` 和 `projectRoot/记忆索引.md`。
2. 按主责 Skill 读取最小核心记录：

| 主责 Skill | 优先记录 |
| --- | --- |
| 规划师 | `学习档案.md`、`当前进度.md` |
| 执行器 | `当前进度.md`、`错题队列.md` |
| 诊断师 | `当前进度.md`、`学习档案.md` |
| 错题闭环、模考 | `错题队列.md`、相关主题笔记 |
| 四科学科 Skill | 相关主题笔记、`错题队列.md` |
| 真题、材料 | 相关主题笔记、`记忆索引.md` |
| 官方核验 | 只读 `学习档案.md` 中的目标；旧笔记不得作为当前官方证据 |

3. 从本轮主题提取科目、知识点和任务词，优先检索 `projectRoot` 与 `30-知识/考研 22408/`；仅当 `retrievalScope` 为 `project-first` 且专属区不足时，才只读检索 Vault 其他 Markdown。
4. 先读索引和摘要，再打开必要正文。单轮最多使用 8 篇笔记、累计最多约 16,000 个字符；不得读取 `.obsidian/`、回收站、归档以外的非 Markdown 私有文件。
5. 只把实际读到且影响回答的内容列在 `[Obsidian记忆]` 段落，附 Vault 相对路径。它是用户历史材料，不是官方事实或模型结论。

## 任务结束：结构化沉淀

只有产生以后仍有价值的新信息时才写入；普通讲题、寒暄、临时状态、重复内容和未采用草稿保持只读。

- 目标、时间预算和稳定约束更新 `学习档案.md`。
- 已确认计划与用户明确报告的完成量更新 `当前进度.md`；刚生成、尚未由用户确认的新计划保持待确认且不写回。计划只能标为 `planned`，不得推断为 `completed`。
- 用户真实暴露的错因、复测安排和掌握证据更新 `错题队列.md`；推测错因标为 `hypothesis`，复测证据满足后才能标为掌握。
- 经多次验证的学习偏好、方法和概念写入 `30-知识/考研 22408/`，优先更新已有主题笔记。
- 经官方核验的事实必须同时保存机构、适用年度、发布日期、直接 URL 和绝对核验日期。
- `StudyProfile`、`ProgressSnapshot`、`ReviewQueue` 继续使用 Schema 1.1；未知值使用 `null`，不反推不存在的数据。

写入时遵守以下顺序：

1. 写入前重新读取目标文件；若内容已变化，合并双方结果并标出待整理项，不覆盖新内容。
2. 遵循 Vault `AGENTS.md`，保留 YAML、使用 `[[双向链接]]`，更新 `00-系统/知识库索引.md` 和 `00-系统/成长日志.md`。
3. 不保存整段会话、密钥、Cookie、身份/支付信息、完整付费资料、长篇版权材料或未授权题库。
4. “忘记/删除”请求先定位具体记录，默认移动到 `90-归档/`；未确认目标前不永久删除。
5. 写入失败时不影响学习回答，输出可复制的便携记录并明确失败原因。

## 输出状态

每次回答在可选交接卡之后、Schema 1.1 JSON 之前输出一行：

- 成功读取并写入：`Obsidian：已读取 N 条记忆；已更新 <相对路径>。`
- 已读取但本轮禁止或无需写入：`Obsidian：已连接；已读取 N 条记忆；写入桥接器可用但本轮只读，无写入。`
- 已连接但无命中：`Obsidian：已连接；未命中相关记忆；无写入。`
- 降级：`Obsidian：未连接（原因）；本轮使用会话信息。`

若没有便携 JSON，状态行放在回答末尾。
