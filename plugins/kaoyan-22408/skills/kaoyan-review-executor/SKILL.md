# 考研复习执行器

## 加载契约

- 始终读取并遵循[能力路由契约](../../references/capability-routing-contract.md)。
- 每次生成 `ProgressSnapshot`，因此读取[便携学习记录契约](../../references/portable-learning-records.md)。
- 仅当引用用户材料、处理来源或生成原创内容时，再读取[证据与版权契约](../../references/evidence-copyright-contract.md)。

## 接受两种输入

1. 用户提供既有计划片段和本次可用时长；保留原计划优先级。
2. 即使没有长期计划，只要用户已给出本次目标、科目和时长，也直接安排这一时段。

跨科不等于跨周规划；单次时段内在多个科目间分配分钟数仍是执行任务。

如果请求涉及跨周配额、阶段取舍或目标日期倒排，转交 `kaoyan-22408-planner`。不要仅因缺少长期计划而拒绝安排单次时段。

## 展开时段

1. 提取本次目标、科目、范围、时长、开始时间、现有材料和硬性中断；只询问会阻止任务开始的最少信息。
2. 只有总时长时使用相对时间盒，不编造具体钟点。只有目标过宽且无法落地时，请用户选择最小范围。
3. 将目标拆成有顺序的时间盒；每项写明动作、输入、产出、完成标准和分钟数。
4. 加入必要休息、切换与收尾回填，使总分钟数严格闭合且不超过预算。
5. 给出时间不足时的缩减顺序：保留核心产出，顺延低优先级任务；不把未完成项描述为已完成。
6. 检查每项是否能立即开始、是否有明确终点、是否擅自改变了长期配额。

## 输出

依次输出：

1. 本次目标与输入依据。
2. 时间盒清单：时长、动作、产出、完成标准。
3. 缩减与中断恢复方案。
4. 严格 JSON 的可回填 `ProgressSnapshot 1.1`；每次都输出。把计划量写入 `metrics[].planned`，尚未发生的 `completed`、`correct`、`total` 和 `rate` 写 `null`，不同单位分项记录。
5. 完成后如何把回填快照交给 `kaoyan-progress-diagnostician`。

只处理当前会话信息，不发现设备文件、不写入状态、不声称拥有长期记忆或已完成任何任务。
