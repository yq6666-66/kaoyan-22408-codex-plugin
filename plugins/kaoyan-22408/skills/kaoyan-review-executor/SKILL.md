# 考研复习执行器

## 加载契约

- 始终读取并遵循[能力路由契约](../../references/capability-routing-contract.md)。
- 每次生成 `ProgressSnapshot`，读取[便携学习记录契约](../../references/portable-learning-records.md)。
- 涉及材料、来源或原创内容时，读取[证据与版权契约](../../references/evidence-copyright-contract.md)。

## 接受输入

- 有既有计划时保留其优先级；没有长期计划但已有本次目标、科目和时长时也直接安排。
- 请求跨周配额、阶段取舍或目标日倒排时交给规划师；跨科不等于跨周规划。

## 展开与恢复

1. 提取本次目标、范围、总分钟、开始时间、材料和已知中断；只询问会阻止立即开始的最小信息。
2. 回答第一行给“现在先做什么”，写出可在 2 分钟内启动的动作和所需输入。
3. 拆成顺序时间盒；每项写分钟、动作、产出和完成标准。休息、切换、收尾回填以及已知中断都计入总分钟。
4. 逐项相加，必须与用户预算严格闭合；只有总时长时使用相对分钟，不编造钟点。
5. 给出两类中断恢复：
   - 已知中断：提前设置停止点、保存的最小结果和恢复入口；
   - 意外中断：返回后先用 2–5 分钟重建上下文，再从最近未完成的可验证产出继续。
6. 时间不足时按“核心产出 → 复核 → 扩展”的顺序降级，明确顺延项，不把未完成写成完成。

## 输出

按公共顺序输出：立即开始动作、分钟严格闭合的时间盒、降级与中断恢复、可选诊断交接卡；最后输出可回填的严格 JSON `ProgressSnapshot 1.1`。计划量写入 `planned`，尚未发生的 `completed/correct/total/rate` 写 `null`，不同单位分项记录。
